# Other board views

> Read when touching the completed board, board preferences, the phone portrait layout or the List (master) view. Moved out of CLAUDE.md verbatim on 2026-09-30; keep adding here, not there.

### Completed tasks board (2026-09-12)
- **A ticked task leaves the day card.** `projects.show_completed` (default 0) gates the completed section in `renderBoard()`; the completion toast says where the row went. The old struck-through-under-a-divider behaviour is the **Show completed tasks on the board** switch on the preferences page. `GET .../projects` carries `show_completed`; `refreshProjectDueFlags()` merges it and a `visibilitychange` listener re-reads it. Focus mode still hides completed rows.
- **The Completed tasks board** is the fourth board-popup row — Preferences · Brief the assistant · Rename · **Completed tasks** (with count) · Delete. `viewMode 'completed'`, own `#completedContainer` (banner · chart · day strip), **not a mode of `renderBoard()`**: a finished row has two answers — **click the circle to reopen** (`toggleComplete`) and **Option+Click the name for its page**. Reads the same `tasks` array (the route returns completed rows too); view toggle becomes "Back to your board".
- **Rows bucket by `scheduled_date`** like the day board. The dashboard buckets by `completed_at`; they can differ for a task completed on a future day — accepted. Window: **30 days ending today** (`COMPLETED_DAYS`), extended past today only for tasks completed ahead; the strip scrolls so today is at the right end.
- **Line chart is hand-drawn SVG, y-axis pinned 0–7** (`COMPLETED_AXIS_MAX` = day capacity; stretches only when beaten). Drawn at measured width (`renderCompletedChart(days, width)`), redrawn on resize — a stretched `viewBox` would squash the labels with the line. Kevin asked for **Jelly UI** (jelly-ui.com, MIT, v1.1.0); **it has no chart element** (40 elements; `jelly-card` is a 36px chip), so Jelly is used where it fits: **`<jelly-switch>` on the preferences page** inside `<jelly-theme mode accent="#0ea5e9">` following `movealong.theme`. Bundle **vendored at `public/vendor/jelly.js` (318 KB, unmodified, licence beside it)**, loaded only by `preferences.html`. Its checkbox lives in shadow DOM, so the page listens on change/input/click/keyup and dedupes on reflected `checked`; a native checkbox stands in if the element hasn't registered after 2s. **Not verified in a real browser** — if it misbehaves in Safari, check the fallback checkbox first; dropping to a plain `<input type="checkbox">` costs nothing.

### Board preferences (/preferences/:projectId, 2026-09-05)
- **Two preferences: lock lagging tasks to today, and show completed tasks.** `projects.autolock_days` (NULL/0 = off, 1-365). Applied in `GET .../tasks` **right after spillover**: a pending, unlocked, non-calendar, non-awaiting, non-review task on **today or earlier** whose **inclusive day count has reached N** (`julianday(today) - julianday(origin_date) + 1 >= N`, the grey counter's number) is set `locked = 1, scheduled_date = today`. From then it's an ordinary lock. **Turning the preference off never unlocks.** **It fires once per task** (`tasks.autolocked`, never cleared) — without that, unlocking was a no-op because the next load re-locked it; Kevin hit this the day after it shipped.
- **Tasks moved to a future day are left alone** (`scheduled_date <= today` guard) — a plan, not a lag. The counter still climbs.
- **A page, not a popup field** (`public/preferences.html`, `GET|PUT /api/projects/:id/preferences`, from the board popup's **Preferences** row). Kevin: "for now, the only preference will be this one," so the page is where the next ones go. Empty string clears; 0 and non-integers 400.

### A phone held upright: one day (2026-09-25)
- **Portrait on a phone shows one day, full width; landscape keeps the row of days** (Kevin). `body.portrait` is set from `matchMedia('(orientation: portrait) and (max-width: 600px)')` (`portraitQuery`, re-rendered on change) — a class, not a bare media query, so the JS that picks the day and the CSS that sizes it can't disagree. The rules are scoped to `#board`; team and completed views are untouched.
- **The board still renders all thirty days**; each `.day-column` is 100% wide with `scroll-snap-type: x mandatory`, so a swipe is a day. `#dayNav` above the board names it ("Today · Sep 25", Tomorrow, Yesterday, else the weekday — the card's own header row is hidden) with ‹ › and a **Today** pill when off today. **Opens on today**, not the overdue anchor. `portraitDayKey` (null = today) survives re-renders — rebuilding the board resets its scroll, so `showPortraitDay()` runs at the end of every `renderBoard()`; a scroll listener reads the settled snap back into it.
- The card is a screen tall (`100svh - 150px`) until a pane opens; in portrait the pane is **`position: static`** under the tasks rather than hanging below a screen-tall card. Hidden in portrait: the tip bar (hover-only), focus toggle (one day is focus), the drag-to-series hint (no drag on iOS). The mail strip drops its body column and keeps its own 24px gap for Accept all (`renderMailStrip()` reads a 0-height tip bar there). `selectDay()` doesn't focus the day's input in portrait — it threw the keyboard up on every tap.
- **Thumb-sized (Kevin, same day):** in portrait, row text 16px, circles 20px, row icons 22px, steps 15px, event lines 15px; **the day counter and repeat glyph stay 10px** (his call). Inputs are 16px so iOS doesn't zoom on focus. **The step rail lies down** (check · assignee · ↑ · 🔎 in a row) — the phone has the width the 178px pane never had. The pane is `position: relative` (not static), or its absolute ↺ anchors to the day column and lands on the first event line.
- **Hover-and-press shortcuts get no touch version** (Kevin: not needed on the phone). Popups still position for a desktop pointer. Verified in jsdom (stubbed `matchMedia`) and a 390px WebKit render, not on a phone.

### Master Project Page
- Each username has a master page listing all projects (button labelled **"List"** since 2026-08-05; internally still `master`). Tasks grouped by project, one pane per project with all open, unassigned tasks. Assigned tasks are removed from both the day pane and the master page.

- **Phone/Mac sync (2026-10-02).** `syncBoard()` in `index.html` re-reads the board's tasks when the tab becomes visible and every 60s while visible, and repaints only if the JSON changed. It skips (and drops a read that returns late) when you're typing in a field, dragging, a draft is generating, the board switched, or the view isn't the day calendar. It does **not** reload an open pane's subtasks, and it isn't live push — a minute's lag at worst. Verified in jsdom: a task added over the API stayed hidden while the add-task input had focus and appeared on the next visibility event after blur.
