# Morning briefing, goals and the sprint

> Read when touching the briefing pane, weather/market, briefing_items, /goals, sprints or Friday reviews. Moved out of CLAUDE.md verbatim on 2026-09-30; keep adding here, not there.

### The morning briefing (2026-09-13)
- **Shape (Kevin's calls):** a **pane under today's card** on the **first board only**, items as **tickable rows**; unticked items are **cleared by the next briefing, never spilled**; mail items **carry a reply draft** as a `mailto:` link. Contents: calendar events, mail count with critical ones summarized, unread texts, the board's goal, one health nudge, **weather for ZIP 38237**.
- **Who does what.** The user's own Claude assembles it through the MoveIt server: `briefing_recipe` returns the steps (also an MCP prompt, `morning-brief`), `post_briefing` replaces the day's items wholesale (max 12, kinds `calendar | mail | text | board | health | note` plus `market`, links only `https: mailto: sms: tel:`), `get_briefing` reads back, `tick_briefing_item` ticks one. **Weather is the server's job, never posted**: `weatherFor()` geocodes the ZIP once via zippopotam.us (cached on `users.zip_lat/zip_lon/zip_place`) and asks Open-Meteo (cached in memory per user per day, no key, fixed hosts, 6s timeout). A ZIP that can't be placed is refused **before** it is written (the first test left the user on ZIP 00000).
- **Store:** `briefing_items` (user, day, kind, text, detail, link, position, done, done_at). `GET/PUT .../briefing[?day]`, `PUT /api/briefing-items/:id {done}`. "Today" without `x-tz` is **`todayKeyForUser()`** — the user's `timezone` setting, then UTC; the MoveIt HTTP endpoint sets `x-tz` from that setting for every tool call.
- **On the board:** `loadBriefing()` runs from `loadTasks()` when the current board is `projects[0]`; `renderBriefingPane()` renders into **today's pane slot** under the single-pane rule (a task opened on today replaces it). Same `.subtask-pane.board-pane` box (so `fitExpandedPane()` measures it), `.briefing-pane` rows: tick circle (blue fill when done, strike), a tiny kind word, the text, `draft ↗` / `reply ↗` / `open ↗` for the link, detail line on click. Weather is one line under the title (`93°/69° partly cloudy · 40% rain`; place in the tooltip). **×** hides it for the day (`localStorage['movealong.briefing.hidden']` = day key). No briefing and no ZIP → no pane.
- **The recipe is Kevin's, verbatim (second version, 2026-09-13)** — mailed from the phone, replaced the first draft wholesale: a **`market`** kind (prior session + up to two items on positions he holds, weekdays only), **no board status roll-up** (only the goal, if set), **nudges only when triggered** (oldest open brief question, a money deadline in the next few days, a trip countdown, whether the sprint project was touched yesterday; max 3), **health only when triggered** (steps under his 8,000 average or a log gap, no gym or yoga in 3+ days; max 2). Order: calendar, mail, market, texts, nudges, health. Edit `BRIEFING_RECIPE` in `mcp/tools.js` only on his word — the assistant reads it live. **The recipe names personal facts in a public repo**; the cleaner home is his brief.
- **Phone → desktop handoff (Kevin's pick): the board is the message bus.** The phone Claude adds a task to the Personal board — "MoveIt: …" — with details in notes (`add_task` + `add_note`). **The desktop session should check for open "MoveIt:" tasks with `list_tasks`/`get_task` when Kevin says "see what the phone sent" or at the start of MoveIt work.** Email works but needs the desktop Gmail connector signed in and leaves no board record; a `messages` table is the upgrade if this becomes weekly.
- **Where you are follows the device (Kevin, 2026-09-26: "always be where I am at the moment").** Once per load the board calls `navigator.geolocation` (`reportLocation()`, from `loadTasks()`; Safari asks permission the first time) and `PUT .../users/:slug/location {lat, lon}` stores it in `users.zip_lat/zip_lon` **rounded to 2 decimals (~1 km)**, replacing them only when moved more than `LOCATION_MOVE_DEG` (0.05°, ~5 km) so jitter doesn't drop the day's cached forecast; it nulls `users.zip`, clears `weatherCache` and names the place via BigDataCloud's keyless `reverse-geocode-client` (failure costs only the tooltip). `weatherFor()` needs coordinates, not a ZIP (a ZIP is geocoded only if there are none). **The ZIP field is gone from preferences** (it now reads "Weather for <place> (last seen)"); `PUT .../settings { zip }` still works for the API. A phone opening the board moves the weather to the phone — that's the point. Denied permission → the weather stays where it last was. **The time zone follows the Mac (Kevin, 2026-09-25): no picker, nothing baked in.** The Mac sets its zone from location; the board (browser) and Tom (stdio MoveIt server, `macZone()`) send it as `x-tz`; **`noteZone()`** silently stores it in `users.timezone` whenever it differs — called only from `GET .../tasks` and the calendar routes (always the person's *own* board; the team view reads `/shared-board`, so a viewer's zone never lands on a teammate). `users.timezone` is just the last zone seen, for callers with none of their own: the phone via `/mcp`, the feed's background sync, research's `user_location`. `PUT .../settings` ignores `timezone`. Gap accepted: fly with the Mac shut and the phone uses the old zone until the Mac next reports (the heartbeat does within 30 min). **Railway's `TZ` variable is irrelevant.** Kevin was in Pacific when this shipped, not Central.
- **The briefing fills itself (Kevin, 2026-09-26: "I'd rather just have the daily brief come up").** The board's own sections render with no assistant and no post, in this order: **weather** (line one the numbers — the daily sky word is dropped when the story exists, because Open-Meteo's daily code is the day's *worst* sky and read "overcast" on a sunny day; line two `weatherStory()`, **rules not a model** (his pick): sky per morning 6–11 / afternoon 12–17 / evening 18–22 by most common hourly code, neighbours merged, "Chance of/Rain likely from 2pm" at ≥ 40%, "Peaks at 91° around 1pm, 71° by 9pm"), then **the market** — `marketFor()`: the tickers on the **shelved list named "Stocks"** on the Lists page (items matching `TICKER_RE`, max 12, order = `sort_order`), quoted from **Yahoo's keyless `v8/finance/chart` endpoint** (unofficial — a failure drops the section), cached 5 min per symbol, **only 9:30–16:00 ET on trading days** (`marketOpen()`, `MARKET_HOLIDAYS` hand-listed for 2026–2027 — **extend it before 2028**); **hidden when closed** (his call). One row per ticker (symbol · price · day %), up blue / down `#b91c1c`, each a link to Yahoo Finance; the page re-reads every 5 min while a market section is showing. Tom's posted items follow. The "ask your assistant" placeholder is gone. **Adding a section later**: something the board can fetch itself (like weather and prices) becomes a server function in `briefingPayload()`; something needing mail, calendar or texts stays in Tom's recipe.
- **Texting is Mac-only and not a MoveIt tool.** **`scripts/mac/text.js <name|number> <message> [--dry]`** (Contacts lookup, ambiguous names listed not guessed, iMessage else SMS relay) and **`scripts/mac/unread-texts.js [--hours N]`** (reads `chat.db` read-only, grouped by thread, JSON; exits 3 when **Full Disk Access** is missing — it is missing on this Mac as of 2026-09-13, so the texts section is empty until Kevin grants it). The recipe says post nothing for texts when unreadable. The Contacts-lookup path was not exercised.
- Verified: settings validation, live geocode + Open-Meteo for 38237, post/tick/cap/`javascript:` link stripped, the tools and prompt over HTTP, the pane through WebKit in both themes. **Two snapshot traps**: the pane's `slideDown` starts at opacity 0 (snapshot needs `animation: none`), and jsdom has no layout so `fitExpandedPane()` reserves nothing — force `padding-bottom` in the copy.

### Goals, the sprint and the Friday review (/goals, 2026-09-29)
- **Why it exists (Kevin, 2026-09-29, in a coaching conversation):** many parallel aims and no ordering between them, planning outpacing output, no long-term project with an external deadline or someone waiting. The one thing that worked was the Monster Spray six-week sprint — "one project, the rest parked, a daily did-I-touch-it, a hard end date". His calls: **the check-in is daily, in the morning brief, at the top (Q1 yes)**; **the Friday review lives on the page, not in conversation (Q2 a)**. Sprint 2 (Oct 8 – Nov 19) is Monster Spray out the door — festival submissions, which come with real deadlines.
- **Shape follows the briefing rule above:** board data the board can compute goes in `briefingPayload()`, not Tom's recipe. `sprintFor(userId, today)` returns the active sprint with day N of M, `yesterday_touched`, streak, the last seven days, `this_week` (the latest review's next_week) and `review_due` (Friday, nothing written for the week ending today). The pane renders it **first under the weather** (`renderBriefingSprint()`): orange kind word and title (orange is the goal colour on the board), *Touched it yesterday?* with **yes / no pills** (`logSprintDay()` → `PUT /api/sprints/:id/days/:day`, optimistic, toast on failure), seven dots, the deliverable line, and on Fridays a link to write the review. Only today's payload carries `sprint`. The pane's "has anything" checks (two sites in `renderBoard()`) include `briefing.sprint`.
- **Tables:** `goals` (rank = position; status active/parked/done), `sprints` (one goal, start/end, deliverable, waiting_on; status planned/active/done/abandoned; **at most one active**), `sprint_days` (UNIQUE sprint+day; touched 1/0; **no row = not asked**, distinct from an honest no), `sprint_reviews` (UNIQUE sprint+week_ending, the Friday). `reference/data-model.md` has the columns, `reference/api-reference.md` the routes.
- **Planned vs active:** POST with a start day after today makes the sprint `planned` and leaves the current one running; `activeSprint()` promotes a planned sprint on its start day **only once no active sprint remains** — an ended sprint nobody closed keeps the slot (pane reads "ended — close it ↗") because that is exactly the thing to see. Starting a sprint *now* closes the active one as done (`close_active: 'done'`) or abandoned.
- **The page** (`public/goals.html`, `/goals`, target icon in the header between Dashboard and Lists): three panes. **Sprint** — title in orange (input, edits in place), goal chip, dates and day N of M, a progress bar, the same yes/no check-in, a **touch grid** (a cell a day, Monday first, like the health streak grid; click cycles unasked → yes → no → unasked; today outlined; days outside the sprint dashed; future blank), deliverable and who's-waiting fields, Close as done / Abandon (one-line outcome via `prompt`) / Plan the next sprint (form defaults to the day after this one ends, six weeks). **Goals** — rank number, title, detail (auto-growing textarea), horizon; hover tools ↑ ↓ ⏸ ✓ ×; add at the bottom. **Friday review** — this week's form (week ends Friday; Sat/Sun still write Friday's) and past weeks below; `#review` anchor focuses it when due. Every field autosaves on focusout with a state word per pane (serialized chain, the brief page's idiom). Reads the person from `localStorage['movealong.session']`.
- **MoveIt tools:** `get_goals`, `log_sprint_day` (default yesterday; only on the user's word), `add_sprint_review` (default this week's Friday). **Recipe step 1 reads `get_goals`; step 7's sprint nudge no longer reads the brief** — it fires only for what the pane can't say (a broken streak still unanswered when Tom runs, three no's before a deliverable is due, an unclosed ended sprint, review due). The brief's "Current sprint project: MoveIt" line is obsolete — delete it on /brief.
