# Calendar import

> Read when touching calendar.js, the 📅 switch, the event band, feed or connector sync. Moved out of CLAUDE.md verbatim on 2026-09-30; keep adding here, not there.

### Calendar import (📅 toggle)
- A **📅 Calendar switch** beside 🧠. Connecting subscribes to a **secret iCal (ICS) feed URL** and mirrors the next **14 days** of timed events as task rows with `source = 'calendar'`.
- **Feed URL, not OAuth:** Google, Proton, iCloud and Outlook all publish one; Proton has no API; the app has no auth for OAuth tokens. Backed by `node-ical` — **the dependency list is four now, not three.** It expands RRULE, EXDATE and `RECURRENCE-ID` overrides; hand-rolling recurrence shows a standup once and never again.
- **Imported rows are deliberately NOT locked.** `locked` drives board anchoring (`computeAnchorKey`), red tabs (`due_today`), red text (`.locked-today`) — all would misfire daily on an event. Day capacity is free: calendar rows carry `project_id = NULL`, bucketed separately by `findDayWithCapacity`.
- **One guard: calendar rows are excluded from spillover**, at *both* sites where `locked` is checked in `GET .../tasks` (the overdue SELECT and the fixed-point loop's re-check). Miss it and yesterday's standup repeats daily forever. Setting `locked` on a calendar row is also refused by `PUT /api/tasks/:id` and the quick-lock.
- **`project_id = NULL` is deliberate** — one row shows on every board; the tasks route filters `(t.project_id = ? OR t.source = 'calendar')`. This is the one place NULL `project_id` is meaningful; a cleanup sweeping NULL project_ids would delete every event.
- **Past events are pruned, not spilled.** An un-completed event leaves no trace; its subtasks cascade-delete. The prune runs **unconditionally**, even when the fetch fails.
- **A failed fetch never reconciles** — a 404 (regenerated secret address) treated as "empty" would wipe the board. Failures record `last_status`/`last_error`, surfaced in the connect popup.
- **Events are matched on `external_uid` and updated in place, never recreated** (subtasks CASCADE). `completed` is never touched. `external_uid` is `UID + '#' + dateKey` (recurring instances share one UID).
- **Rendering: the band (2026-09-23, Kevin's pick of `archive/cal-v1..v3.html`, built by `archive/cal-build.js`).** Events are facts, not tasks: `renderBoard()` splits `source = 'calendar'` rows out of the day's task lists entirely and `renderEventBand()` draws them **between the date and the add-task box** as quiet lines over a hairline — **titles in a task's colour, not grey** (Kevin, 2026-09-25; the time stays grey) (`.ev-band` / `.ev-line`): **circle · title · time on the right** (Kevin, 2026-09-24; `2:05p` via `eventClock()`). No counter or pane — they never take one of the seven rows. **They do have → since 2026-09-28 (Kevin: "the move arrow … the same way we have it for tasks"), and it reschedules *at the source*, never on the board** (his pick): every sync resets the board's copy, so `eventHome()` opens the event where it lives — a Google event's own page (`event_link`, the connector's htmlLink; uid ends `@google.com#<date>`), else Google's day view; anything else (iCloud feed events carry no link) opens iCloud Calendar on the web. **`.ev-arrow` is its own class on purpose**: reusing `.task-arrow` would let hover-and-press-a-digit PUT a new `scheduled_date` on an event. **The marker (`.ev-circle`, a rounded square 14px, radius 3, 2px border since 2026-09-28 (a rectangle for an hour first) — Kevin wanted events to look different from tasks; it was the task circle's 14px round before) ticks the event off** through `toggleComplete()`: it leaves the band (back, struck, under the board's show-completed preference) and counts under "Calendar" on the dashboard. **Ticked events are history, so they are never deleted** — `prunePastEvents()`, `deleteAllEvents()` and both paths' stale-prune all skip `completed = 1`; only unticked past events vanish. **Plain for every source** (Kevin: Gmail-made events look like the rest). Today's events fade (`.past`, 40%) once they end. Hover → tip bar (span · title · place · gestures). **Click opens `event_link`; Option+Click makes a prep task** on the event's day — "Before <title> (3:30p)", drafted like any task, the event as its background (`prepTaskForEvent()`, the mail strip's Make-task idiom). The old `.task-item.calendar` row CSS and `sortByPosition`'s calendar branch still exist for the team view, which renders rows. Pre-band subtasks on an event are orphaned from view (none existed on production).
- **Titles are trimmed of filler (Kevin, 2026-09-24: "Appointment with City Eyeworks" → "City Eyeworks").** `tidyEventTitle()` in `calendar.js` strips a fixed list of leading phrases (`Invitation:`, `Reminder:`, `Appointment/Meeting/Call/Visit/Reservation with|at|for`) on **both** paths, never to empty; the connector recipe asks Claude to go further with judgment (shortest words that say what it is, ~24 chars). "Call with Jay" → "Jay" is the accepted cost of the fixed list.
- **Two ways in (Kevin: "both").** The secret-address feed (automatic, 15 min) and **Claude through the Google Calendar connector** (`PUT .../calendar/events`, MCP `post_calendar` + `calendar_recipe` / prompt `calendar-sync` — runs only when asked until Tom's heartbeat exists). Shared `reconcileEvents()` in `calendar.js`; rows match on `external_uid` whichever path wrote them (the connector derives Google's feed UID from the event id: `<id minus _<start> suffix>@google.com`), keep the path that created them (`event_via`), and **each path prunes only its own**. A feed's whole-day link never overwrites an event's own link. The 📅 switch reads on while connector rows exist; its popup says how many and when.
- **And one way back out:** the task's 📅 popup has **Add to Google Calendar** — Google's own prefilled new-event form (`googleCalendarLink()`, all-day on the task's day, task page in the details). No credentials; the saved event comes back through either path as a line in the band.
- **Sync is lazy and fire-and-forget** from `GET .../tasks` on a 15-minute throttle with an in-flight guard. **`syncFeed` must call `flushDb()` itself.**
- **Timezone:** the feed sync reads `users.timezone` (follows the Mac; `calendar_feeds.timezone` is a leftover, used only if that's empty); day keys derived with `toLocaleDateString('en-CA', { timeZone })`. **`node-ical` already re-anchors recurrences across DST** — do **not** add an offset correction (double-shifts every recurring event).
- **Filtering:** drop all-day events, free/`TRANSP:TRANSPARENT` (Google's holidays and birthdays), `X-MICROSOFT-CDO-BUSYSTATUS:FREE`, `STATUS:CANCELLED`.
- **Labelled Beta** in help (`.beta-badge` on the section `h2`, `.card.beta` amber, `.beta-note`) and in the 📅 popup title (`.beta-tag`). Amber, not red or blue. The privacy story is left open in copy ("still being figured out"): no password, event titles readable by anyone with the link, feed URL stored server-side — point it at a spare calendar.
- **Calendar has its own help section (2026-08-17)** — `<h2>Add calendar events</h2>` after Subtasks, before Run your own copy. Three cards: overview (demo + margin note), **Finding your calendar link** (Google / iCloud / Outlook paths), **Proton Calendar** with a `Paid plan` badge (share link is paid; free-plan users have no way in — a support question waiting to happen).
- `docs/animation/build.js` **strips `.beta-badge` spans from a scene's title** before slugifying.
- **The feed URL is a bearer credential.** Stored server-side, returned masked, never in localStorage. SSRF surface: https only, private/loopback/link-local rejected, 10s timeout, 5 MB cap, 500-event cap.
- Calendar rows are **absent from the List view** (filters `t.project_id = ?`). Intended.

- **The 📅 header icon is gone (2026-10-02).** Tom's heartbeat keeps events fresh, so the icon was nearly always idle. Its popup (connect / sync now / turn on-off / disconnect / last error / connector status) is now the **Calendar pane on the preferences page** (`preferences.html`, user-level like "Where you are", reached from the board tab's menu › Preferences). Same routes (`GET|PUT|DELETE .../calendar`, `POST .../calendar/sync`). The board no longer loads calendar status; the Calendar section of help.html points at Preferences.
