### The MoveIt server — the board as an MCP server (server/mcp, 2026-09-13)
- **Kevin calls it "the MoveIt server"** — use that name in prose and in agent instructions. The registered Claude Code name is still `movealong`; renaming means re-running `claude mcp add` (his step). **The product was renamed MoveIt the same day**: tab titles, help prose, signup default; the wordmark reads Move**It**.
- **Kevin's Q1 on agents: architecture B** — the board holds no credentials and runs no agents; it exposes MCP tools and the user's own Claude (Claude Code on the Mac with Gmail/Calendar connectors and Messages/Contacts on disk) does the work and writes back. Primer: `reference/agents-primer.md`. **Q2: briefing items are tickable rows. Q3: the first dashboard is health — steps, weight, gym, entered by hand.** His "el12 MCP server" reply meant *explain like I'm 12*; the server was built on that misread and kept.
- **`server/mcp/index.js`**, own package (ESM, `@modelcontextprotocol/sdk` + `zod`). Stdio transport. **Talks to the board over REST, never the database**; env: `MOVEALONG_URL`, `MOVEALONG_TEAM`, `MOVEALONG_USER`, `MOVEALONG_AI_KEY`; `x-tz` is the Mac's zone read from `/etc/localtime` on every call (`macZone()`), not an env var — Node fixes its zone at startup and this process lives as long as the session. Fourteen tools: `list_boards`, `list_tasks`, `add_task` (today by default, optional background / lock / `draft_steps`), `update_task`, `get_task` (row + page + notes + steps), `add_note`, `set_results`, `add_step`, `tick_step`, `promote_step`, `get_brief`, `append_brief` (dedupes case-insensitively), `set_contact_field`, `completions`. Boards resolve by name (case-insensitive) or id, default the first tab; a bad name errors with the list.
- **It also runs over the web (2026-09-13)** for the Claude phone app: tools moved to **`server/mcp/tools.js`** (`createMoveItServer({urlBase, team, user, aiKey, tz})`), `mcp/index.js` is the stdio wrapper, and `server.js` mounts the same set at **`/mcp/:secret`** as stateless Streamable HTTP (fresh server + transport per request; SDK loaded lazily by dynamic `import()` from the CJS server). Bound to one person by `MCP_TEAM` / `MCP_USER`; `MCP_SECRET` is the whole lock (timing-safe, 404 without it); the phone app sends no `x-tz`, so "today" comes from `users.timezone`, the last zone the Mac reported (`MCP_TZ` is gone). Tools call the server's own REST routes over loopback with `AI_ACCESS_KEY`. **This put `@modelcontextprotocol/sdk` and `zod` in the main server's dependencies (six now)**; `mcp/package.json` carries none — its files resolve from `../node_modules`. Phone setup: Settings › Connectors › Add custom connector, URL with the secret, no OAuth. Verified over the SDK's HTTP client and stdio.
- **Registering it is Kevin's step**: `claude mcp add movealong -s user -e … -- node /Users/moon/MoveAlong/server/mcp/index.js` (in `server/mcp/README.md`) — the AI key goes in env there, never a checked-in `.mcp.json`. `npm install` in `server/mcp` first; Railway doesn't build it.
- Verified over stdio against a throwaway board: every tool, dedupe, bad-board error, `x-tz` making `list_tasks.today` the Chicago date. Nothing logs to `step_events` beyond what routes already log.
- **The 2026-09-13 MCP commit shipped without these docs** — a multi-file `patch()` script asserted on a stale CLAUDE.md anchor after writing `index.js`, and the unchained `git commit` ran anyway. Second time this fired (see Conventions).

### Tom — the doing agent (direction 2026-09-16; first skill built, no board plumbing yet)
- **Kevin named the AI agent Tom.** The premise: some tasks Tom can do himself ("send my RMH invoice"), so he should notice, ask what he needs, do the work, and present the output for review. **Draft only, unless Kevin grants autonomy for that task in words** (Q2). **Heartbeat: a Claude Code scheduled run every 30 minutes** drains Tom's queue (Q3). Whether Tom replaces Tessa is open (Q1).
- **Specialization = skill files, not different brains.** Kevin pictured specialist agents (production, HR/ops, accounting); the mechanism is one model plus a bundle of skills, tools and credentials per specialty — and the narrower tool access per bundle is the safety win. So **skills are step zero**: `.claude/skills/<name>/SKILL.md` (checked in) with scripts in `scripts/tom/`. The offer at draft time fires only when a skill matches; no match → "Tom can learn this".
- **Planned build order:** (1) offer at draft time — the phase 1 draft returns `agent_offer`, a quiet Tom chip on the row, one button in the pane; (2) the run reuses Tessa's plumbing (assign to an AI auto-accepts, finished work comes home as a review row with Results on the task page); (3) an `agent_runs` queue + `list_runs`/`claim_run`/`finish_run` MoveIt tools drained by the desktop Claude; (4) the ladder — three accepted offers of the same kind → runs on sight, two rejections → retired.
- **`rmh-invoice` is the first skill** (`.claude/skills/rmh-invoice/SKILL.md`, `scripts/tom/invoice.js`, config `scripts/tom/clients/rmh.json` — **gitignored**: it carries his rate, retainer and the client contact; `example.json` ships). Pattern read off the 2025–26 invoices: dated the 1st, $2,100 retainer, "Additional <previous month> hours" × $225, expenses, total; invoice # and filename `RMH <Mon> <year>` with his month spellings (June, July, Sept). Renders with **pdfkit** (pure JS, Helvetica, one sky-blue bar — no Pages, no browser), refuses to overwrite, and records the invoice in **the receivables ledger: `ledger.csv` beside the invoices is the record and `ledger.html` beside it is the view** (`scripts/tom/ledger.js`; Kevin opens the page in Safari). **A Google Sheet was built first and deleted the same day** — Kevin: keep it HTML, no connections; and the Drive connector can create a sheet but not append to one, so it needed a service account anyway. The page can't write to disk, so changes are commands (`paid`, `paid-through`, `open`) that Tom runs on his word. Financial data stays off the live site (no auth). The Gmail connector's `create_draft` takes base64 attachments, so Tom leaves a draft with the PDF on it. **Tom asks for the hours** — Kevin totals them by hand; never guess. Recipient email is unknown (`email: null`) until read off the last sent thread.
